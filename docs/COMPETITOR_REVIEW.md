## 1. Быстрые выигрыши

Дёшево сделать, эффект заметен сразу.

### 1.1. Нормализация громкости до −14 LUFS

- **У них:** clippyme (post-process каждого клипа, EBU R128) и hotclip (экспорт).
- **У нас:** нормализации нет, поэтому клипы получаются разной громкости.
- **Что сделать:** добавить фильтр `loudnorm=I=-14:TP=-1.5:LRA=11` в финальное кодирование (`scripts/video_processor.py`). Лучше двухпроходный вариант: первый проход измеряет, второй применяет.

### 1.2. Края клипа по паузам вместо `reel_padding: 5`

- **У них:**
  - clippyme, `pipeline/cut_ops.py::refine_edges_to_silence`: начало клипа сдвигается к концу ближайшей тишины, конец — к её началу. Паузы берутся из ffmpeg `silencedetect`. Край двигается только если граница тишины близко, а при любом конфликте остаётся как был.
  - hotclip, `src/core/speech-activity.ts`: детектор речи Silero VAD, край сдвигается не больше чем на 0,6 с, с запасом 0,08 с в начале и 0,12 с в конце.
- **У нас:** фиксированные 5 с запаса с каждой стороны. Клип обычно начинается посреди предыдущей фразы и заканчивается началом следующей.
- **Что сделать:** заменить фиксированный padding подгонкой к паузам в звуке. Детектор тишины у нас уже есть в `analysis/audio_features.py`, но для уличных записей порог нужно считать от средней громкости: на POS200926 абсолютный порог −32 дБ не нашёл ни одной паузы.

### 1.3. Правила качества без LLM

- **У них:** hotclip, `src/core/highlight/gate.ts`. Клип понижается до «проверить», если:
  - начинается с союза-продолжения («а», «и», «но», «так что», «поэтому»), то есть это обрывок фразы;
  - кончается на запятой;
  - в нём слишком часто меняются говорящие.

  Итог — одна из трёх меток: публиковать / проверить / не публиковать. Правила могут только понизить метку, а «не публиковать» ставит только LLM. Их обоснование: 30–45% автоклипов — брак, а за брак алгоритмы платформ режут охват всего аккаунта.
- **У нас:** есть штраф `penalize_mid_thought` в `analysis/scoring.py`, но он смотрит на заголовок, а не на первые и последние слова цитаты. Меток нет.

### 1.4. Кривая «самые пересматриваемые» с YouTube

- **У них:** clips-studio, `analysis/hype.py::_youtube_heatmap`: поле `heatmap` из информации yt-dlp добавляет к оценке небольшой бонус с ограничением сверху.
- **У нас:** `.info.json` мы уже скачиваем (`sources/episode_metadata.py`), но `heatmap` не читаем. Для популярных роликов это готовый сигнал зрительского интереса.

### 1.5. Имена и термины как подсказка распознаванию

- **У них:** FunClip (hotwords через SeACo-Paraformer) и hotclip (глоссарий, общий для всех эпизодов).
- **У нас:** глоссарий из метаданных YouTube идёт только в вычитку. В транскрипции есть ручной `initial_prompt`, но нет `hotwords`.
- **Что сделать:** передавать в faster-whisper `hotwords` из глоссария и метаданных эпизода.

## 2. Крупные улучшения качества

### 2.1. Субтитры: сборка из слов и точные тайминги

План уже согласован 2026-09-25.

**Как у них:**
- **tscaps**, `packages/engine/src/modules/document/Segment.ts`, `modules/splitting/*`:
  - реплика — это только группа слов;
  - время реплики — от начала первого слова до конца последнего;
  - режут сначала по паузам ≥ 0,5 с (`PauseBasedSegmentSplitter`), затем по пунктуации, затем по длине: примерно 18–40 символов, в лучшем месте;
  - единственная правка таймингов — конец слова обрезается по началу следующего (`WordOverlapClamper`).
- **clippyme**, `domain/subtitles.py::generate_srt`: реплика не длиннее 20 символов и 2 с, разрыв на конце предложения.
- **clips-studio**, `video/captions.py`: 3 слова на реплику, заглавными.
- **hotclip**, `src/core/align.ts`: второй проход только для финалистов. Модель — Paraformer с временными метками по CIF, заявленная точность ±50 мс. Выравнивание по LCS символов, при низком совпадении — откат к исходным таймингам. Каждое слово помечено: `aligned` или `interpolated`.
- **clipsai:** транскрипция через WhisperX, то есть с forced alignment.
- **captacity:** распознаёт звук уже готового клипа, так что тайминги и звук совпадают по определению.

**Что сделать у нас:**
1. **Переписать сборщик реплик «от слов».**
   - Порядок разрезов: паузы 0,4–0,5 с → конец предложения и запятые → лимит символов.
   - Для шортсов реплики короче, чем сейчас: примерно 1 строка до 20–25 символов вместо 2 строк по 28.
   - Не растягивать начало реплики и не сдвигать соседние. Конец можно продлевать только в следующую за ним тишину.
2. **Тайминги слов — forced alignment вычитанного текста клипа по его звуку:** wav2vec2 для русского, как в WhisperX. Второй проход Whisper этого не заменяет.
3. **`subtitles.whisper_sync`** — убрать или оставить только отчётом, без правки таймингов.
4. **Помечать происхождение тайминга** (выровнено / восстановлено) в `subtitle_sync.json`.

Караоке остаётся выключенным (`subtitles.karaoke: false`).

**Что уже сделано** (не закоммичено на 2026-09-25):
- исправлена главная причина рассинхрона: фраза, обрезанная границей клипа, теперь получает текст только из слов, попавших в клип;
- пересекающиеся реплики обрезают предыдущую, а не сдвигают следующую;
- начало слова ограничено правдоподобной длительностью (артефакт Whisper «пауза втянута в слово»);
- добавлены флаг караоке и `utils/subtitle_sync.py`.

### 2.2. Сравнение финалистов друг с другом

- **У них:** clips-studio, `analysis/fusion.py::_rerank` и `config/prompts/rerank.txt`. Маленькие модели дают абсолютные оценки в узком диапазоне, поэтому финалистов пачками по 8 упорядочивают друг относительно друга одним вызовом. Место в порядке даёт небольшую прибавку (0–6 из 100) и никогда не понижает оценку. Ответ — `{"order": [...]}`, частичный или повторяющийся список чинится.
- **У нас:** judge ставит абсолютную оценку 1–10 батчами (пункт C4/S1 аудита `ANALYSIS_REPORT.md`).
- **Что сделать:** после judge — один вызов переранжирования по топу, результат как бонус к `priority`.

### 2.3. Кандидаты по сигналам, а не только по тексту

- **У них:**
  - clips-studio, `analysis/fusion.py`, `audio_features.py`, `visual_features.py`: сигналы звука (пики громкости, частые всплески вроде смеха и аплодисментов, переход «тишина → взрыв»), картинки (смены сцен, движение) и реакций, посекундно. Каждый нормируется внутри видео. Окна с пиками становятся отдельными кандидатами, а LLM видит временную шкалу событий.
  - hotclip, `src/core/highlight/moments.ts`: кривая «жара» по 8 сигналам с весами по жанру.
- **У нас:** звук — только поправка к оценке уже найденных текстовых кандидатов (`analysis/audio_features.py`). Момент, где слова слабые, а реакция сильная, теряется.
- **Что сделать:** посекундная кривая громкости и всплесков по эпизоду, пики как дополнительные кандидаты и строка «события» в промпте scout.

### 2.4. Промпт отбора: сначала фильтр, потом оценка

- **У них:** clippyme, `pipeline/gemini_request.py::GEMINI_PROMPT_TEMPLATE`.
  - **Фильтр до оценки** — момент должен пройти хотя бы по одному признаку:
    - неожиданный поворот;
    - сильная эмоция или спорность («разделит комментарии»);
    - узнаваемость («это же про меня»);
    - новый или полезный факт.
  - **Рубрика** — 5 осей по 20 баллов: захват в первые 1–3 с, эмоциональная развязка, цитируемость, понятность без контекста, плотность без пустот.
  - **Правила:**
    - реакция (смех, пауза после откровения) — часть клипа, резать после неё;
    - смена говорящего — естественная точка разреза;
    - «меньше, но сильнее»: слабый клип вредит аккаунту больше, чем отсутствующий.
- **У нас:** `prompts/*/chunk_*.txt` и `judge_*.txt` без фильтра и без явной рубрики.

### 2.5. Динамическое кадрирование

- **У них:**
  - clippyme, `pipeline/reframe.py`, `reframe_ops.py`, `reframe_track.py`: YOLOv8 + MediaPipe FaceMesh. Говорящего определяют по колебаниям раскрытия рта. Режим «comfort»: внутри сцены камера неподвижна, одна степень зума на сцену, при сильном движении — статичный широкий кадр.
  - clips-studio, `video/tracker.py`, `video/podcast.py`: TalkNet (кто говорит — по лицу и звуку вместе). При смене говорящего кадр переключается резким переходом, без проезда. В подкаст-режиме у каждого плана своя неподвижная рамка.
  - Сцены делят PySceneDetect.
- **У нас:** `utils/face_crop.py` — одна неподвижная рамка на весь клип (или split на двоих). Детекции смены сцен нет. На многокамерных подкастах рамка ломается после первой смены плана.
- **Сделано 2026-10-03:** `utils/face_track.py` — склейки планов, треки лиц (YuNet), говорящий по губам и звуку (Light-ASD) + Витерби, плавное слежение с мёртвой зоной; всё на GPU.

### 2.6. Аудиограмма для эпизодов без видео

- **У них:** hotclip, `src/core/audiogram.ts`: волна плюс цитата, вертикальный клип из чистого аудио.
- **У нас:** YouTube по умолчанию скачивается только звуком (`youtube.download: audio`), и такие эпизоды дают статью и транскрипт, но ни одного клипа.

## 4. Что у нас уже не хуже

Чтобы не переделывать лишнее:

- **Цитата как доказательство.** Точная и нечёткая проверка по транскрипту, жёсткие пороги, `rejected_candidates.json`. Из конкурентов ближе всего hotclip (сверка цитаты по транскрипту), остальные доверяют таймкодам LLM.
- **Решения cleanup и judge по `candidate_id`.** Модель физически не может сдвинуть клип или переписать цитату.
- **Детерминированный отбор.** MMR, квоты, допустимое пересечение клипов, дедуп по цитате.
- **Вычитка транскрипта LLM** с переносом таймингов слов, глоссарий из метаданных YouTube.
- **Метрики прогона** в `analysis_metrics.json`, отпечатки стадий и повторные запуски, кэш ответов LLM, автономный режим с отчётом.
- **Split-кадр на двух собеседников.**
